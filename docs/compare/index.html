Ways to let an AI agent use your Mac, compared

Containers, script runners, pointer-and-screenshot servers and the accessibility tree: where each approach to computer use draws its line, and how to pick one on purpose.

There are four common ways to let an AI agent operate a computer today. They are not better or worse in general; they fail in different places. This page says where each one draws its line, so you can pick on purpose. Disclosure: Computer MCP is made by Agent360, who wrote this page. The other projects are described from their own READMEs, linked below, and we have not benchmarked them.

The four approaches

1. A desktop in a container or VM, driven through screenshots

Anthropic's computer use demo is the reference: a Linux desktop in Docker with X11 and VNC, an agent loop, and the Anthropic-defined computer tools (screenshot, click, type). Sandbox projects such as Cua build on the same idea with cross-OS sandboxes. What you get: a real boundary. The agent can only reach what is inside the box. What it costs: the box is not where your work is. Your signed-in apps, files and sessions have to be brought in, and the demo's own README recommends a dedicated VM or container, keeping sensitive data out, and a human confirming consequential decisions.

2. Script runners (AppleScript and JXA)

Servers such as macos-automator-mcp run AppleScript and JavaScript for Automation on your Mac. What you get: precise, fast control of scriptable apps, with no screenshots at all. What it costs: it reaches only what an app exposes to scripting, and a script can do anything the language allows, so what is safe depends on the script the model writes.

3. Pointer, keyboard and screenshot servers on your own machine

Servers such as automation-mcp give the agent mouse, keyboard, screen and window control on your Mac. What you get: anything you could do by hand. What it costs: the agent uses the same pointer and keyboard you do, so the machine is busy while it works, and every screenshot is a picture of your real screen.

4. The accessibility tree, behind your windows (Computer MCP)

Computer MCP reads and operates apps through the macOS accessibility API. It presses buttons and fills fields in windows that stay behind the one you are in, and leaves your pointer where you put it. Secure text fields and password-manager windows are painted black on the bitmap in memory before a screenshot is written, password managers are refused, deleting and sending ask first, and every call lands in an append-only log. What it costs: it is macOS only today, an app that draws its own controls and publishes no accessibility tree is a blind spot, and consent is not containment: after you approve, the agent drives your real Mac. If you need a boundary rather than a decision, use approach 1.

How to choose

  1. The task touches accounts you cannot afford to lose. Use a VM or container, and bring in only what the task needs.
  2. The app is scriptable and you know the script. A script runner is the fastest and quietest option.
  3. The work is on your own Mac, in apps that are not scriptable, while you keep working. That is the case Computer MCP was built for.
  4. The work is inside web pages. Use a browser tool for the page itself, such as Browser MCP for your signed-in Chrome, and let Computer MCP handle what the browser tool cannot reach. See Browser MCP and Computer MCP together.

FAQ

What is the safest way to let an AI agent use my Mac?

If you need a hard boundary, a virtual machine or container: the agent can only reach what is inside it. If the work has to happen on your own Mac, choose a tool that keeps passwords out of screenshots, asks before destructive actions and keeps a log you can read back. Computer MCP does those three, and its own README says plainly that consent is not containment.

How is Computer MCP different from Anthropic's computer use demo?

The demo runs a Linux desktop in Docker and drives it with screenshots, clicks and typing. Computer MCP runs on your own Mac, works through the accessibility tree in windows behind yours, and blacks out password fields before a screenshot is written. The demo gives you isolation; Computer MCP gives you your real apps with consent and an audit log.

Does Computer MCP work on Windows or Linux?

Not yet. It is macOS 14+ today. Linux and Windows are on a public roadmap (GitHub issue #42), and nothing will be claimed for them until CI proves it. Contributions are welcome, and several tasks are marked good first issue.

Is Computer MCP free?

Yes. It is MIT licensed, runs locally, and needs no account or API key. Install it with npx @agent360/computer-mcp in any MCP client, such as Claude Code, Cursor, VS Code or Codex.

Can I use it together with a browser automation MCP server?

Yes, and that is the recommended setup for web work: the browser tool works inside pages, and Computer MCP takes over where the browser tool is refused, for example native dialogs and other apps.
