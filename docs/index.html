New to this?

You install it once, and your assistant gets abilities it did not have before. That is all an MCP server is: a small program that hands your assistant a set of tools. This one hands it your Mac.

It runs on your own machine. There is no account to make, no key to paste, and nothing is sent to us. Your assistant keeps talking to whichever AI you already pay for: Claude Code, Cursor, VS Code, Codex, Windsurf, Zed or your own agent, with the same one line.

What leaving it running looks like

Each of these is something you can check afterwards, in a log you can read back. The lines are examples in the shape the server writes, shortened. Typed text never appears in them.

  1. It works behind your window

    Most tools click by moving your real pointer, which lands wherever you happen to be typing. This one presses a button through the app’s own accessibility action, in a window that stays behind yours, and every keystroke, click and press answers with took_screen, so you never have to take our word for it.

    "tool":"computer_press", "target":"com.apple.Preview", "decision":"allowed" "tool":"computer_press", "outcome":"ok", "effect":"performed", "took_screen":false

  2. It says when it failed

    The most common complaint about agents driving a computer is that they carry on as if it worked. Here a refusal or a failure comes back as one, with the reason, and the same reason is written down. When three buttons could be the one you meant, it refuses instead of guessing.

    "tool":"computer_press", "outcome":"error", "error":"ambiguous", "message":"found 3 matches - narrow the search, pick one with index, or pass --first"

  3. Several can run at once

    No session lock, no one-at-a-time limit. Every line carries the session it came from, so the log says which conversation did what. Two agents typing into the same app take turns; two agents in different apps do not wait for each other.

    "session":"3e6f9a44", "client":"claude-code", "tool":"computer_type" "session":"54c41ca8", "client":"cursor", "tool":"computer_find"

  4. Your passwords stay yours

    Keychain, 1Password and seven others ask every time, in every mode, and a password manager can never be approved from the menu bar. Password fields are painted black while the screenshot is still in memory, before it is ever a file.

    "target":"com.1password.1password", "decision":"denied", "reason":"background mode: this would need a dialog, and a dialog takes the screen (a password app can never be approved from the menu bar)"

  5. The few things that need you, wait for you

    Anything that deletes or clears, a message to a real person, and starting a screen recording do not happen on their own. The menu bar icon turns orange and the question waits there, with the whole action written out. You allow it with Touch ID. Nobody answering is a no.

    "tool":"computer_press", "target":"net.whatsapp.WhatsApp", "asked":true, "asker":"menubar", "decision":"allowed"

The long versions, with the failure modes: working while you keep using your Mac and leaving it running overnight.

What you can ask it to do

Not a feature list. Things people ask for, and what happens.

You sayWhat it does
“What’s on my screen right now?” Takes a picture and reads it. Any password box in it is painted black before the picture exists as a file.
“Fill in this form for me.” Finds the fields by name rather than guessing at pixels, and writes into them, in a window sitting behind the one you are using, without taking your cursor.
“Export this, then tell me when it’s done.” Picks File › Export from the menu (much of what a Mac can do has no button at all, only a menu), then waits for the result instead of taking a hundred screenshots while it waits.
“Do this in Slack.” Slack, VS Code, Discord and Notion hide their buttons from most tools until asked. It asks first. Measured on a VS Code fork with two windows open: 0 buttons before, 728 after.
“Log in to this and carry on.” Puts the cursor in the password box and asks you to type. It never sees what you typed; there is deliberately no way to hand it a password.
“What did you do while I was out?” Reads back the log it kept: every action, in order, with the app it happened in.

If none of that is your problem, that is a fine answer too. When not to use it names the cases where something else is better, including our own browser tool for anything inside a web page.

Install it in three steps

It starts ready to work: twenty-five of the thirty-two, no asking, except your password manager, anything that deletes or clears, a message to a real person, and starting a screen recording. It runs in the background by default, so nothing takes your screen; CMCP_BACKGROUND=0 adds the seven that do.

What you get today, honestly. npx @agent360/computer-mcp currently serves 0.1.0, which has 12 tools. The 32 tools described here are the source: they are built and tested, but not published yet. Building from source takes about thirty-five seconds if you want them now.

  1. Add it to your client

    Claude Code:

    claude mcp add computer -- npx -y @agent360/computer-mcp

    Cursor, VS Code, Codex, Windsurf: in mcp.json,

    {"mcpServers":{"computer":{"command":"npx","args":["-y","@agent360/computer-mcp"]}}}

  2. Grant two permissions

    System Settings › Privacy & Security › Accessibility and Screen Recording, for the app that runs the server. No Swift needed: the package ships a universal binary for Apple silicon and Intel. It carries the ad-hoc signature macOS needs to run it at all, not a Developer ID signature, and not notarized, so Gatekeeper may ask the first time.

  3. Ask it what it can see

    Ask your agent to call computer_permissions. It tells you what is still missing, and which rules in Claude Code’s settings would let an agent walk around this server’s gates.

Step by step, with the permissions part spelled out: Claude Code, Codex, Cursor, GitHub Copilot, Claude Desktop, VS Code. If an agent is setting this up for you, point it at llms-install.md. Two pages worth reading before you install rather than after: when this is the wrong tool, and how to remove it and exactly what it touches.

CMCP_MODEWhat happens
readonlyThe write tools are not even listed. The agent can see your Mac and cannot touch it. Good for research, and for the first hour.
askOne consent dialog per session in front of the first write; after that it works. Password managers, anything that deletes, a message to a real person, and starting a screen recording still ask every time.
allowDefault. Writes go through without asking, all of them logged. Password managers, anything that deletes or clears, a message to a real person, and starting a screen recording still ask. None of that is configurable, on purpose.

Twenty-seven seconds of the real thing

No sound, and you can pause it. Every line in the log is a line the server actually writes.

A password field is blacked out before the screenshot becomes a file, a write action waits for a yes, and every line in the log carries a fingerprint of itself and the line before it, so a removed or edited line breaks the chain and says where.

How we know the gates hold

Each gate has a test in the repository, and each test has been mutation-checked: break the code on purpose and the test goes red. A promise without a test that can fail is just a sentence.

Every change is built and tested on a Mac on GitHub before it can land: the redaction test, 22 checks of the security claims that need no permissions, and the audit log under several writers at once. See the runs.

Passwords never reach the model
Secure fields are found by role and subrole, because a password box in a web page is a plain text field with a secure subrole. Checking only the role would let every browser password box through.
The dangerous places ask first
Password managers ask every time, terminals and editors once per session, and any action whose target app cannot be identified asks every time. If nobody answers, the answer is no.
Everything is written down
An append-only log, mode 0600. Typed text is stored as a length and a salted fingerprint, never in clear; an audit trail full of passwords is its own breach. If the log cannot be written, write actions are refused until it can.
No second bill
There is no model inside this server. The one driving your agent does the seeing and the thinking; Computer MCP only supplies hands.

What it does not do

Being straight about the edges is cheaper than being found out at them.

macOS only
It is built on the macOS accessibility and screen capture APIs. There is no Windows or Linux build, and none is planned.
Not the inside of a web page
In Chrome you get the browser’s own window (tabs, toolbar, address bar), not the page. Measured: 29 buttons before and after asking. For a page, drive the browser with a browser tool.
Apps that draw their own controls
It reads the accessibility tree, so an app that paints everything on a canvas and publishes nothing, like some games and plotting tools, is still a blind spot.
Redaction covers marked fields
It blacks out what macOS marks as secure, plus password-manager windows. A password sitting in a plain text editor is not marked secure, and it will not pretend to find it. Use readonly when the screen holds something it cannot know about.
Consent is not a sandbox
Once you approve a session, the agent can drive your real Mac. That is the point. If you need containment rather than consent, run it in a VM.
Prompt injection is still real
A web page can try to talk your agent into something. The questions and the log turn that from silent into visible. They do not make it impossible.

Questions

Does anything leave my machine?

No. There is no account, no telemetry and no server of ours involved. Screenshots go to the MCP client you configured, the same place the rest of your conversation goes, and nowhere else.

The same rule holds for this website: no analytics, no cookies, no third-party requests. The only <script> tag anywhere on the site is application/ld+json structured data, which your browser does not execute, never a program. View source and check.

How is this different from the other macOS MCP servers?

Capability-wise, not enormously: screenshots, clicks, keystrokes, the accessibility tree. The difference is what happens in the hours you are not watching. It works in windows behind the one you are in and leaves your pointer where you put it, so it does not take over the machine while you use it. It tells you when something failed instead of carrying on as if it worked. Several can run at once. And it will not go near your password manager. If you only ever watch it work, most of that is wasted on you.

Does it ask me before it does things?

Not for ordinary work: it acts, and every call lands in the log. A few things never happen without a person saying yes: your password manager, anything that deletes or clears, sending a message, and starting a screen recording. In the default mode they wait in the menu bar icon, which turns orange; a password manager cannot be approved there, so it is refused. If you would rather be asked once up front, CMCP_MODE=ask puts one session-granting dialog in front of the first write, and ignoring it refuses the action rather than allowing it.

Why is the audit log fingerprinted instead of plain?

Because a complete record of every keystroke is exactly the file an attacker would want. The fingerprint proves two actions typed the same thing without ever storing what it was. It is scrambled with a random ingredient that only exists while it runs; a fingerprint without that random ingredient, of an eight-character password, is guessable offline, which would have made the log the very thing this promise is against. The cost is honest: comparison works within a run, not across runs.

Can I turn the redaction off?

Yes: redact: false on a single screenshot. It is per call and never sticky, and the result says plainly that the image was not redacted.

Does it work in Claude Code’s auto mode?

Partly. Auto mode judges every call on its own, so expect some refusals. The tools that take the screen are refused: measured on 1 October, auto mode turned them down even after the person had lent the screen with Touch ID. That is the client’s own guard, not this server’s, and it is right to be careful. To use them, run the session without auto mode and approve each call when Claude Code asks; the gates in this server still apply on top.
